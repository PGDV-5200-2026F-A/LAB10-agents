# ANSUR Anthropometric Dashboard

Model signature: deepseek-v4.1-flash

An interactive, dependency-light dashboard for exploring the ANSUR (U.S. Army)
anthropometric dataset: distributions of individual body measurements and the
relationships between them. It renders a **scatter plot**, a **covariance /
correlation matrix heatmap**, and three **distribution** views — a **box plot**,
a **violin plot**, and a **histogram (bar)**.

## How to run

Open the file directly — there is no build step and no data server:

```
ansur/index.html
```

Double-click it, or open it from a browser (`file:///.../ansur/index.html`).
The dataset is embedded in `ansur/data.js` as `window.ANSUR`, so nothing is
fetched at runtime except the pinned D3 library from a CDN. To work fully
offline, download `d3.min.js` (7.9.0) next to `index.html` and change the
`<script src>` in `index.html` to point at the local copy.

### Regenerating the data (optional)

`ansur/data.js` and `ansur/summary.json` are generated by `ansur/prep.py` from
`data/ansur-full.csv` (Python 3 standard library only):

```
python3 ansur/prep.py
```

The dashboard no longer needs to be rebuilt afterwards; it reads `data.js` at
load time.

## Data source

* `data/ansur-full.csv` — ANSUR I/II anthropometric survey measurements.
* `ansur/data.js` — 6,068 records × 18 columns, embedded for offline use.

Columns: `age`, `gender`, and 16 body measurements (`height`, `weight`, `span`,
`stature`, `ear.*`, `foot.*`, `hand.*`, `head.*`). `gender` ∈ {`M`, `F`}.

## The unit trap (important)

**Units are mixed.** `height` is in **inches**, `weight` is in **pounds**, `age`
is in **years**, and every other body measurement is in **millimetres**.

Consequences enforced by the dashboard:

* Every axis label states its own unit (`stature (mm)`, `weight (lb)`, …).
* Raw values from different unit groups are **never** placed on one shared axis.
* The covariance heatmap defaults to the **correlation** matrix, which is
  unit-free and therefore comparable across the mixed columns. Raw covariance
  is available via a toggle but is inherently unit-dependent (a covariance cell
  mixes different units), so its cells are shown as colour + tooltip only, with
  the units spelled out in the tooltip. The covariance colour scale is fitted to
  the **off-diagonal** covariances; the diagonal (a variance, typically orders of
  magnitude larger) is drawn in a fixed neutral grey and excluded from the scale,
  otherwise it would wash out every other cell.

## Missing values and implausible values

* **800 missing cells** exist across `span` (138), `ear.protrusion` (210),
  `head.breadth` (205), `foot.length` (135), `ear.length` (69), `hand.palm` (27),
  `hand.length` (12), `hand.breadth` (2), `head.length` (1).
* Missing values are preserved as JSON `null`. **No imputation is performed
  anywhere** in the pipeline. Each statistic excludes the nulls it cannot use and
  reports the `n` it actually summarised (seen in tooltips, the feature-stats
  line, and the matrix's pairwise `n`).
* **One implausible value**: a recorded `weight` of 0 lb (source row index 1496).
  `prep.py` recoded it to `null`, so the dashboard shows it as missing. It is not
  "fixed" further and no value is invented for it.
* **Zero duplicate rows.**

The KPI row surfaces the filtered record count, per-gender counts, and the total
missing cells for the current gender filter, so the data-quality picture is
always visible rather than hidden.

## Statistical methods

All statistics are computed in the browser from `window.ANSUR.records`, so they
respond to the gender filter. The definitions deliberately match `prep.py` (and
`summary.json`):

* **Pairwise-complete covariance** — each matrix cell is computed from only the
  rows where *both* variables are present (not row-wise deletion). Hence the
  **pairwise n** shown for the selected cell; a coefficient built on fewer rows
  is visibly less certain.
* **Sample covariance**, **n − 1** denominator.
* **Quantiles by linear interpolation** — the same definition as `d3.quantile`
  (used for box/violin quartiles, medians, and the descriptive statistics).
* **Pearson r is derived from the same covariance matrix**,
  `r = cov(a, b) / (sd_a · sd_b)`, so the covariance and correlation views can
  never disagree. The scatter plot reuses this r for the selected pair.
* **Diagonals**: covariance diagonal = variance of the available cases for that
  column (n − 1); correlation diagonal = 1.
* The least-squares trend line in the scatter is fit on the full pairwise-complete
  set, using `slope = cov / var(x)`.

`summary.json` contains the independently computed descriptive statistics,
covariance matrix, correlation matrix, and pairwise counts, in the same
definitions, for verification of the JS output.

## Interactions

* **Gender filter** (All / Male / Female) — applies to every view and KPI.
* **Feature select** — drives the box, violin and histogram and the scatter
  x-axis.
* **Scatter y select** — drives the scatter y-axis.
* **Matrix scale** — toggles between correlation (default) and covariance.
* **Click a matrix cell** — loads that (row, column) pair into the scatter plot
  and highlights the cell.
* **Tooltips** — rich per-element detail. Nothing essential is *only* available
  on hover: the selected feature's full five-number summary + mean + sd is printed
  under the distribution row, and the selected cell's r, covariance, pairwise n
  and strength rating are printed in the matrix detail panel.

All controls are native, keyboard-reachable inputs with real `<label>`
associations.

## Design decisions and defaults

* **Determinism.** D3 is pinned to `d3@7.9.0`. There is no `Math.random()`, no
  `d3-random`, and no transitions or animations. Widths/heights/margins/viewBox
  are fixed. Records are sorted explicitly before every data binding (e.g. by
  x value, then gender, then the stable source index). SVG `defs` use stable
  string ids (`matrix-legend-gradient`).
* **Scatter sampling.** At most 4,000 points are drawn using a **deterministic
  stride** — every k-th record with `k = ceil(n / 4000)` — over records sorted by
  (x, gender, source index). The number of points shown and the stride are printed
  on the page under the scatter title; the sample is never random.
* **Distribution scales.** The box, violin and histogram share the same feature
  min–max range (the observed data range, with at most a 2–3% visual pad), so the
  three views are directly comparable and no axis is truncated. Box/violin
  whiskers and extents span the data min–max (a plain five-number summary).
  Violin densities share one width scale (the common maximum density) so groups
  are comparable.
* **Gender encoding.** Paul Tol "bright" blue/orange, which is distinguishable
  under common colour-vision deficiencies. In the scatter, gender is additionally
  encoded by **shape** (circle = Male, triangle = Female); in the distribution
  charts the gender is named on the axis. Meaning never rests on colour alone.
* **Matrix palette.** A blue → near-white → red diverging scale. Each correlation
  cell also prints its value, and the label colour is chosen for contrast against
  the cell background, so the number — not the colour — is the primary encoding.
* **Responsiveness.** Fixed-size SVGs scale down via `viewBox` + `max-width: 100%`;
  the card grids collapse to fewer columns at narrow widths.

## Verification notes

Everything rendered is derived from `window.ANSUR.records` in `ansur.js`; no
statistic is copied into the page as a literal. `ansur.js` recomputes the same
quantities `prep.py` wrote to `summary.json`, so the two can be compared directly
(the plan's "Statistical Check"). Rendered output was verified by inspection of
the source; a JS runtime was not available in the authoring environment, so the
in-browser numbers were checked against `summary.json` by re-deriving the same
formulas rather than by execution.
